# Backend для вашей игры

Это готовый **Backend-шаблон**, который используется для разработки вашей игры.

В нём уже подготовлена базовая структура проекта, которую вы сможете использовать, изменять и дополнять по мере разработки своей игры.

---

# 🚀 Как запустить Backend

### 1. Установите зависимости

Откройте терминал в папке проекта и выполните:

```bash
npm install
```

Эта команда установит все необходимые зависимости проекта.

---

### 2. Создайте `.env`

В проекте есть файл:

```text
.env.example
```

Сделайте его копию и переименуйте в:

```text
.env
```

После этого откройте `.env` и установите необходимые значения конфигурации.

---

# ⚙️ Конфигурация

### Database

```env
DATABASE_URL=postgresql://postgres@localhost:5432/game_db?schema=public&sslmode=disabled
```

Для учебного проекта это значение **не изменяем**.

Оно указывает на локальную PostgreSQL-базу данных `game_db`.

---

### Режим работы

```env
MODE=dev
```

Для разработки используем:

```text
dev
```

---

### Основные настройки

```env
CORE_PORT=3000
CORE_HOSTNAME=domain.com
CORE_PATH=.
CORE_NAME=dev-game
```

Здесь находятся основные настройки Backend:

* `CORE_PORT` — порт, на котором запускается Backend.
* `CORE_HOSTNAME` — домен, на котором будет работать приложение.
* `CORE_PATH` — путь к проекту.
* `CORE_NAME` — название приложения.

На этапе локальной разработки часть этих значений может использоваться в соответствии с настройками вашего проекта.

---

### API и адрес игры

```env
API_BASE_HOST=domain.com
GAME_APP_URL=domain.com
```

* `API_BASE_HOST` — адрес API QR Mint. Через него ваш Backend взаимодействует с инфраструктурой QR Mint.
* `GAME_APP_URL` — адрес вашей игры.

---

### Telegram Bot

```env
GAME_BOT_TOKEN=Установить bot_token из BotFather
```

Здесь необходимо указать `bot_token` вашего Telegram-бота.

Токен можно получить через **BotFather** в Telegram.

**Важно:** токен нельзя публиковать в GitHub или передавать другим людям.

---

### QR Mint Private Key

```env
GAME_PRIVATE_KEY=PRIVATE_KEY
```

Здесь используется Private Key, полученный в QR Mint.

Этот ключ используется Backend для выполнения необходимых операций, связанных с Blockchain.

**Важно:** Private Key является секретным значением. Никогда не публикуйте его в GitHub.

---

### Blockchain addresses

TON:

```env
GAME_TON_ADDRESS=ВАШ_TON_ADDRESS
```

EVM:

```env
GAME_EVM_ADDRESS=ВАШ_EVM_ADDRESS
```

Здесь необходимо указать ваши адреса:

* `GAME_TON_ADDRESS` — ваш TON Address.
* `GAME_EVM_ADDRESS` — ваш EVM Address.

# 📁 Структура Backend

Теперь разберёмся, **что находится внутри Backend и зачем нужен каждый каталог**.

## `config`

Здесь находятся настройки проекта.

Например:

```text
config/network.json
```

В этом файле находятся настройки Blockchain-сетей.

Например, `decimals` используются для правильного преобразования числовых значений в формат, который используется конкретным Blockchain.

---

## `passport`

Каталог, связанный с **авторизацией пользователей**.

Здесь находится логика, необходимая для идентификации пользователя и работы с его авторизацией.

---

## `game-bot`

Здесь находится код Telegram-бота вашей игры.

Именно здесь будет располагаться логика взаимодействия игрока с игрой через Telegram.

Например:

* команды;
* кнопки;
* сообщения;
* действия пользователя;
* взаимодействие с Backend.

---

## `middlewares`

Middleware — это промежуточная логика, которая выполняется перед обработчиком запроса.

Она может использоваться для:

* проверки доступа;
* авторизации;
* проверки данных;
* получения информации о пользователе;
* передачи данных дальше в Router.

Проще говоря:

**Request → Middleware → Router**

Middleware может решить:

> «Можно ли этому пользователю выполнить данный запрос?»

---

## `modules`

Здесь находится часть **логики самой игры**.

Например, здесь могут находиться функции и системы, которые отвечают за:

* игровые данные;
* Score;
* уровни;
* награды;
* игровые действия;
* другую бизнес-логику.

По мере разработки своей игры вы будете добавлять сюда собственную логику.

---

## `public`

Здесь находятся публичные файлы, которые Backend может отдавать пользователю.

Например:

* изображения;
* иконки;
* другие необходимые файлы.

Если игре необходимо загрузить или предоставить пользователю какой-либо публичный файл, он может находиться здесь.

---

## `utils`

Здесь находятся дополнительные вспомогательные функции.

Это функции, которые используются в разных частях Backend и не относятся напрямую к конкретному модулю.

Например:

```text
форматирование данных
проверка значений
работа с датами
вспомогательные преобразования
```

---

## `routes`

Здесь находятся **Router'ы** — маршруты API.

Router определяет:

> какой запрос пришёл → что с ним делать → какой результат вернуть.

Например:

```text
GET /api/player
POST /api/score
GET /api/leaderboard
```

Можно представить это так:

```text
Frontend
   ↓
   API Request
   ↓
  Routes
   ↓
Middleware
   ↓
Game Logic
   ↓
Database
   ↓
Response
   ↓
Frontend
```

Именно через этот механизм ваша игра будет взаимодействовать с Backend.

# 🎮 Что мы будем делать дальше

После того как Backend запущен, мы постепенно будем разбираться, как устроена эта система и как подключить её к вашей игре.

Наша задача — не просто использовать готовый Backend.

Мы будем понимать:

**Frontend → API → Backend → Database → Game**

А затем добавим необходимые игровые системы:

**Player → Score → Levels → Leaderboard → GameFi**

Главная цель — научиться самостоятельно собирать полноценную игру, а не просто копировать готовый код.
